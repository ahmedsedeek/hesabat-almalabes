# نظام إدارة الأعمال والحسابات — تجارة وتصنيع الملابس

تطبيق سطح مكتب لنظامي **Windows** و **macOS**، عربي بالكامل ومن اليمين لليسار،
يعمل دون إنترنت على قاعدة بيانات محلية، ويغطي دورة العمل كاملة:
شراء بضاعة جاهزة أو خامات ← تصنيع لدى المصانع ← مخزون ← بيع (جملة · تجزئة · أونلاين)
← تحصيل ← مرتجعات ← تقارير مالية.

| | |
|---|---|
| **التقنية** | Electron · React · TypeScript · SQLite |
| **قاعدة البيانات** | محلية (SQLite) — مصدر الحقيقة الوحيد |
| **المحاسبة** | قيد مزدوج كامل؛ كل رصيد مُشتقّ من القيود |
| **قنوات البيع** | جملة · تجزئة · أونلاين مع فصل إيراد الشحن عن تكلفة التوصيل |
| **المخزون** | دائم بطريقة المتوسط المرجَّح المتحرك |
| **النسخ الاحتياطي** | محلي تلقائي مشفّر + نسخ إلى مجلد سحابي |
| **الاستيراد** | عملاء · موردون · منتجات · أرصدة مخزون · **فواتير بيع كاملة** من Excel |
| **الاختبارات** | ٩٨ اختبارًا آليًا + فحص ذاتي داخل Electron (٤٨ فحصًا) |

---

## التشغيل السريع

```bash
npm install          # يُرجم الوحدات الأصلية لبيئة Electron تلقائيًا
npm run dev          # تشغيل في وضع التطوير
npm test             # تشغيل كل الاختبارات
npm run build        # فحص الأنواع + بناء الحزمة
npm run selftest     # فحص ذاتي شامل داخل Electron
npm run dist:mac     # توليد مثبّت macOS (dmg + zip)
npm run dist:win     # توليد مثبّت Windows (exe) — يُنفَّذ على ويندوز
```

> مثبّت ويندوز يُبنى على جهاز ويندوز (أو عبر `.github/workflows/release.yml`)،
> لأن أداة ضبط أيقونة الملف التنفيذي لا تعمل على ماك بمعالج Apple Silicon.

> **ملاحظة للمطوّرين:** `better-sqlite3` وحدة أصلية مرتبطة بـ ABI معيّن.
> السكربت `scripts/use-abi.mjs` يبدّل تلقائيًا بين نسخة Node (للاختبارات) ونسخة Electron (للتشغيل)
> ويحتفظ بكليهما في `.native-cache` فلا تُعاد الترجمة في كل مرة.

## بنية المشروع

```
src/
├── shared/              أنواع وثوابت مشتركة بين النواة والواجهة
│   ├── money.ts         تمثيل المبالغ (أعداد صحيحة — لا float إطلاقًا)
│   ├── date.ts          تواريخ محلية (لا UTC) لتفادي انزياح اليوم
│   ├── permissions.ts   مفاتيح الصلاحيات والأدوار الافتراضية
│   ├── errors.ts        أخطاء برسائل عربية + تسلسل آمن عبر IPC
│   └── types.ts         أنواع المجال
│
├── main/                العملية الرئيسية — كل منطق العمل هنا
│   ├── db/              المخطط، الهجرات، الاتصال، بيانات التهيئة
│   ├── accounting/      شجرة الحسابات ودفتر الأستاذ (القيد المزدوج)
│   ├── inventory/       المخزون الدائم والمتوسط المرجَّح
│   ├── services/        خدمات المجال (مبيعات، مشتريات، إنتاج، مدفوعات…)
│   ├── reports/         التقارير ولوحة المعلومات
│   ├── backup/          التشفير والضغط والنسخ والاستعادة
│   ├── print/           قوالب HTML العربية وتوليد PDF
│   ├── ipc/             مسارات الاستدعاء + فحص الصلاحيات
│   └── selftest.ts      الفحص الذاتي الشامل
│
├── preload/             الجسر الآمن (قناة واحدة، بلا وصول مباشر للنظام)
└── renderer/            واجهة React عربية RTL
    └── src/
        ├── components/  مكتبة عناصر الواجهة والتخطيط
        ├── pages/       الشاشات
        ├── lib/         الاتصال بالنواة والتنسيق
        └── store/       حالة الجلسة والواجهة
```

## المبادئ التي بُني عليها النظام

1. **قاعدة البيانات والمحاسبة أولًا، ثم الواجهة.** صُمِّم المخطط وقواعد القيد والمخزون
   واختُبرت بالأرقام قبل كتابة أي شاشة.
2. **لا يُحذف سجل مالي أبدًا.** الإلغاء يُنشئ قيدًا عكسيًا ويُسجَّل في سجل المراجعة مع السبب.
3. **كل رصيد مُشتقّ.** لا يوجد حقل رصيد يُعدَّل يدويًا؛ الأرصدة تُحسب من القيود والحركات.
4. **العملية كلها أو لا شيء.** الفاتورة والمخزون والقيد والدفعة تُحفظ في معاملة واحدة.
5. **لا أرقام عشرية للمال.** كل المبالغ أعداد صحيحة بالوحدة الصغرى.
6. **الواجهة لا تلمس النظام.** كل شيء يمرّ عبر قناة IPC واحدة تُفحص فيها الصلاحيات.
